# 软件团队管理实操方案

> 适用场景：7 人嵌入式软件团队、芯片方案公司、多客户项目并行
> 目标：解决任务分配不合理、沟通欠缺、项目遗漏三大问题
> 落地周期：4 周搭框架，2 个月跑顺

---

## 一、问题诊断

| 表象 | 根因 | 解决方向 |
| --- | --- | --- |
| 工资高的任务少，工资低的任务多 | 1. 任务难度未分级<br>2. 高工资人员的"隐性产出"未计入<br>3. 历史定薪与现有能力不匹配 | 任务分级 + 职责书面化 + 工作量可视化 |
| 团队沟通欠缺 | 1. 缺固定沟通节奏<br>2. 信息只在小圈子流转<br>3. 没有 1-on-1 渠道暴露暗流 | 站会 + 周会 + 1-on-1 三层机制 |
| 项目漏关键项 | 1. 靠记忆而非系统<br>2. 销售/FAE 口头提需求<br>3. 无统一入口和 review 节奏 | 看板单一入口 + 每周 review + 里程碑预警 |

核心判断：**这三个问题是一体的。** 任务靠惯性分 → 高薪员工实际产出难评估 → 沟通不畅积压不满 → 项目散落各处无人统筹 → 漏单。解必须一起解。

---

## 二、任务分配重新设计

### 2.1 任务难度分级（S/A/B/C 四级）

| 等级 | 定义 | 典型任务 | 期望承担者 |
| --- | --- | --- | --- |
| **S** | 架构级、跨模块、需技术预研 | 新芯片平台适配、协议栈架构调整、性能优化攻关 | 高级工程师（>5年） |
| **A** | 模块级、独立交付、有不确定性 | 新 feature 开发、客户定制方案、疑难 bug 攻关 | 中级工程师（3-5年）+ 高级带 |
| **B** | 功能级、流程明确、有参考 | 现有 feature 移植、常规 bug 修复、demo 工程 | 中级工程师独立完成 |
| **C** | 任务级、机械重复、风险低 | 编译测试、文档整理、回归测试、客户答疑 | 初级工程师 / 测试 |

**关键规则：**
- 高级工程师 S/A 占比应 ≥ 70%，B/C 占比 ≤ 30%
- 初级工程师 B/C 占比 ≥ 60%，A 级在带教下参与
- 每周看板上每人 S/A/B/C 任务数清晰可见

### 2.2 隐性工作显性化

高工资人员的价值往往在"看不见"的地方，必须在职责中明确并计入工作量：

| 隐性工作 | 计入方式 | 占比建议（高工资人员） |
| --- | --- | --- |
| 架构设计 / 技术预研 | 独立任务卡，标 S 级 | 20% |
| Code Review | 每次 review 记 0.5 工日 | 10% |
| 带新人 / 答疑 | 固定带教时段，1对1每周2小时 | 10% |
| 文档沉淀 / 知识库 | 独立任务卡，按文档数计 | 5% |
| 跨部门对接（FAE、销售、客户） | 按会议次数+工时记 | 5% |
| 实际开发交付 | 主线 | 50% |

### 2.3 岗位职责模板（每人一份）

```
姓名：______
职级：______
薪资带：______（公司内部）

【负责模块】
主负责：______（须能独立架构）
备负责：______（须能 hold 住主负责人不在时的问题）

【季度核心产出】
1. 交付类：______（具体项目/feature）
2. 沉淀类：______（文档/知识库/工具）
3. 培养类：______（带几个人到什么水平）

【任务等级要求】
S 级任务占比：______%
A 级任务占比：______%
B/C 级任务占比：______%

【考核维度】
- 交付质量（量产事故、bug 数）：______%
- 交付效率（按时率）：______%
- 团队贡献（review、带教、文档）：______%
- 技术沉淀（专利、组件复用）：______%
```

## 三、沟通机制（三层）

### 3.1 每日站会（10 分钟，站着开）

- **时间**：每天上午 9:30，固定不变
- **形式**：在工位区域围成圈，不进会议室
- **议程**：每人三句话
  1. 昨天完成了什么（对应看板哪张卡）
  2. 今天计划做什么
  3. 有没有阻塞需要协助
- **禁止**：讨论技术细节、追问、扯远。有问题站会后单独拉人

### 3.2 周例会（60 分钟，周一上午）

| 时段 | 内容 | 负责人 |
| --- | --- | --- |
| 0-10 min | 上周交付回顾（看板红/黄/绿） | 经理 |
| 10-30 min | 本周项目进度 + 风险 | 各项目 owner |
| 30-45 min | 跨模块依赖、客户问题对齐 | 全员 |
| 45-55 min | 技术分享（轮值，5-10 min） | 轮值人 |
| 55-60 min | 决策 & 行动项 | 经理 |

**输出物**：会议纪要发群里 + 行动项录入看板。

### 3.3 1-on-1（每人每周 30 分钟）

详见 [第五章 1-on-1 谈话提纲](#五1-on-1-谈话提纲)。

## 四、项目看板设计

### 4.1 工具选择

| 工具 | 适合场景 | 备注 |
| --- | --- | --- |
| **飞书项目 / 飞书多维表格** | 国内团队首选，集成 IM | 推荐 |
| **Tower** | 轻量、上手快 | 备选 |
| **Jira** | 流程完整但重 | 团队≥15人再用 |
| **禅道** | 开源、ALM 完整 | 自建服务器 |

**关键**：选哪个不重要，重要的是**只用一个**，杜绝任务散落在微信、邮件、口头。

### 4.2 看板分层结构

```
公司项目总览（顶层）
├── 项目 A（客户1）
│   ├── 需求池
│   ├── 进行中
│   ├── 测试中
│   ├── 已发布
│   └── 风险/挂起
├── 项目 B（客户2）
│   └── ...
└── 内部研发
    ├── 平台优化
    └── 工具/知识库
```

### 4.3 任务卡字段设计（核心）

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| **任务ID** | 自动编号 | ✓ | 系统生成，便于追踪 |
| **任务标题** | 文本 | ✓ | 动词开头，如"修复 SPP 断连后重连失败" |
| **所属项目** | 下拉单选 | ✓ | 关联到顶层项目 |
| **任务类型** | 下拉单选 | ✓ | 需求 / Bug / 优化 / 文档 / 客户支持 / 预研 |
| **难度等级** | 下拉单选 | ✓ | S / A / B / C |
| **负责人** | 人员单选 | ✓ | 唯一责任人，不允许"小组负责" |
| **协作人** | 人员多选 | ✗ | 参与但不背锅的人 |
| **优先级** | 下拉单选 | ✓ | P0 阻塞量产 / P1 影响交付 / P2 计划内 / P3 可延后 |
| **提出来源** | 下拉单选 | ✓ | 客户 / 销售 / FAE / 测试 / 内部规划 |
| **客户名称** | 下拉单选 | 条件必填 | 若来源为客户/销售则必填 |
| **创建时间** | 日期 | 自动 | 系统填 |
| **计划开始** | 日期 | ✓ | |
| **计划完成** | 日期 | ✓ | |
| **实际完成** | 日期 | ✗ | 完成时填 |
| **预估工时** | 数字（人日） | ✓ | 大于3人日的需拆分 |
| **实际工时** | 数字（人日） | ✗ | 完成时填，用于复盘估算偏差 |
| **状态** | 下拉单选 | ✓ | 待办 / 进行中 / 阻塞 / 待测 / 已完成 / 已取消 |
| **风险等级** | 下拉单选 | ✓ | 🟢 正常 / 🟡 关注 / 🔴 告警 |
| **阻塞原因** | 文本 | 条件必填 | 状态为阻塞时必填 |
| **依赖任务** | 任务关联 | ✗ | 上游任务ID |
| **里程碑** | 下拉单选 | 条件必填 | 关联项目里程碑（如"客户A送样") |
| **验收标准** | 文本 | ✓ | 必须写明可验证的标准，禁止"做完即可" |
| **附件** | 文件 | ✗ | 需求文档、log、原理图等 |
| **备注/讨论** | 评论流 | ✗ | 所有讨论沉淀于此，禁止微信私聊 |

### 4.4 状态流转规则

```
待办 ──→ 进行中 ──→ 待测 ──→ 已完成
            │                
            ↓                
          阻塞 (须填阻塞原因 + @经理)
            │                
            ↓                
         进行中 (解除阻塞后)
```

**强制规则：**
1. 销售/FAE 提需求必须在看板上提单，禁止微信口头交代（这条最难但必须立）
2. 阻塞超过 2 天自动升级，经理介入
3. 状态变更必须本人操作，不允许代填
4. 每张卡必须有"验收标准"，否则不允许进入"进行中"

### 4.5 经理每周看板 Review（30 分钟，周五下午）

| 检查项 | 动作 |
| --- | --- |
| 所有 🔴 红色任务 | 当周必须有动作或决策 |
| 所有 🟡 黄色任务 | 评估是否升级红色 |
| 阻塞超过 3 天的任务 | 强制介入解决 |
| 本周里程碑 T-3 检查 | 不能交付的提前预警客户 |
| 下周里程碑 T-7 检查 | 评估风险 |
| 每人 S/A/B/C 任务分布 | 是否符合职级期望 |
| 客户提单响应时长 | 平均响应是否 < 24h |

## 五、1-on-1 谈话提纲

### 5.1 通用原则

- **频率**：每周一次，每人 30 分钟，雷打不动
- **地点**：会议室或安静咖啡区，**不在工位**
- **形式**：你 7 成时间在听，3 成时间在说
- **禁止**：1-on-1 谈进度（进度去看板/站会谈），1-on-1 谈"人"
- **记录**：自己记笔记，不要让员工觉得在被"留底"
- **保密**：员工说的话，未经允许不能传给其他人

### 5.2 标准提纲（适用所有人）

**开场（2 分钟）**
> "最近怎么样？工作之外有什么事吗？"
> （让对方放松，不直接进工作）

**工作感受（10 分钟）**
- 这周做的事，哪件最有成就感？哪件最痛苦？
- 现在手上的任务，难度合适吗？是太简单还是太难？
- 跟哪些同事合作多？合作顺畅吗？
- 有没有什么事让你想吐槽但一直没说？

**成长（8 分钟）**
- 最近学到了什么新东西？
- 接下来 3 个月，你想在技术上突破哪块？
- 我能在哪些方面帮到你？（资源、机会、培训）

**对团队/我的反馈（5 分钟）**
- 团队现在有什么让你觉得别扭的地方？
- 我作为经理，哪些地方做得让你不舒服？哪些可以做得更好？
- 你觉得我们团队最大的问题是什么？

**收尾（5 分钟）**
- 下周你最想推进的一件事是什么？
- 有没有什么我现在能帮你解决的？
- （如果你有要传达的事）补充1-2个重点

### 5.3 场景化提纲

#### 场景 A：跟"高工资但任务少"的员工谈

**目标**：重新对齐价值定位，让对方主动承担难活，而非简单"加任务"。

| 阶段 | 话术 |
| --- | --- |
| 开场 | "想跟你聊聊咱们后面的分工，你来这个团队最久/资历最深，我希望听听你的想法。" |
| 探询现状 | "你现在手上的活，你觉得能发挥你多少能力？打分 1-10 的话？"<br>（不要直接说"你任务少"，让他自己评估） |
| 抛出期望 | "我对你的期望，不是做多少张卡，而是这几件事：<br>1. 团队的架构方向是不是对的<br>2. 难啃的硬骨头你来牵头<br>3. 中初级工程师能不能从你身上学到东西" |
| 听他反馈 | "你觉得这个定位对吗？有没有不同想法？哪些你愿意做，哪些觉得不合适？" |
| 共同制定 | "那我们一起列一下，接下来一个季度你的核心三件事是什么？S/A 级任务怎么定？" |
| 透明底线 | "我得跟你说实话，团队里有人觉得高薪和产出不匹配，我希望咱们用产出说话。"<br>（这句必须说，否则对方意识不到问题严重） |

**注意：**
- 如果谈完发现对方能力确实跟不上高薪，给 1-2 个季度观察期，期间帮他成长
- 观察期结束仍不达标，走绩效调整或岗位调整流程
- 不要拖，拖着对团队伤害更大

#### 场景 B：跟"工资低任务重"的员工谈

**目标**：让对方感到被看见，避免离职，同时不轻易承诺加薪。

| 阶段 | 话术 |
| --- | --- |
| 开场 | "我注意到你最近承担了很多，先跟你说声辛苦。" |
| 认可具体事 | "比如上周 X 项目的客户问题，你跟到深夜两点解决，这事我记着。"<br>（必须举具体例子，否则像客套） |
| 探询感受 | "你自己怎么看现在的工作量和回报？说实话，不用顾忌。" |
| 听不要打断 | （让他抱怨完，记下要点） |
| 区分诉求 | 听完后区分：<br>- 工作量大 → 看板上看是否能调整任务<br>- 待遇问题 → 不当场承诺，说"我会带回去评估"<br>- 成长焦虑 → 提供学习机会和带教 |
| 给具体承诺 | "我能现在承诺你的是：<br>1. 接下来调整任务分配，把 X 类琐事从你这里挪走<br>2. 下个季度让你 lead Y 项目（成长机会）<br>3. 待遇这块我去找老板沟通，X月X日前给你答复" |
| 关键 | 给的承诺一定要兑现，**宁可少承诺也不要食言**。 |

#### 场景 C：跟"沟通有问题"的员工谈

**目标**：理解对方为什么不沟通，而非指责。

| 阶段 | 话术 |
| --- | --- |
| 开场 | "我想聊聊咱们团队最近的沟通，先想听听你的视角。" |
| 探询 | "你觉得团队信息流通顺畅吗？哪些事你是最后才知道的？"<br>"有没有事你想说但觉得没渠道说？" |
| 不预设立场 | （他说同事不好沟通时，先听，不站队） |
| 找具体场景 | "上次 X 事情，你当时是怎么想的？为什么没在群里说？" |
| 一起想办法 | "那你觉得，我们什么样的机制能让你更愿意说？站会？群里？还是私下找我？" |

#### 场景 D：发现员工有离职苗头

**信号**：突然按时下班、请假频繁、对工作冷淡、回避眼神接触。

> ⚠️ **不要直接问"你是不是要离职"**，会逼他做决定。

| 阶段 | 话术 |
| --- | --- |
| 关心切入 | "最近感觉你状态不太一样，是工作上的事，还是生活上有什么？" |
| 给空间 | "如果不方便说也没关系，但你知道有事可以找我。" |
| 探询动机 | "你来咱们公司也 X 年了，当初是冲什么来的？现在那个东西还在吗？" |
| 给可能性 | "如果有什么我能帮你调整的，比如换项目、换方向、加学习机会，你告诉我。" |
| 不挽留过头 | 如果对方已决定走，不要苦苦挽留，体面送别比留下心不在的人更好 |

### 5.4 1-on-1 后的动作

每次 1-on-1 结束后，自己填一份简表（不给对方看）：

```
日期：______ 员工：______
本次状态评估（1-5 分）：______
- 工作满意度：____
- 团队归属感：____
- 离职风险：____

关键信息：
- ______

我承诺的事项（必须跟进）：
- ______ 截止：______

下次 1-on-1 重点：
- ______
```

## 六、4 周落地路线图

### 第 1 周：搭骨架

| 周几 | 动作 | 输出 |
| --- | --- | --- |
| 周一 | 选定看板工具（推荐飞书项目） | 工具确定 |
| 周二-周三 | 把所有在跑项目、任务录入看板（求全不求美） | 看板初版 |
| 周四 | 全员开会，宣布新机制（站会+周会+看板）和规则 | 团队对齐 |
| 周五 | 销售/FAE 同步：以后提需求走看板提单 | 跨部门规则 |

### 第 2 周：跑节奏

| 动作 | 频次 |
| --- | --- |
| 每日站会（10 分钟） | 每天 |
| 周一周例会 | 周一 |
| 周五看板 Review（自己） | 周五 |
| 调整看板字段、修补流程 | 滚动 |

**这周重点**：让团队习惯节奏，不强求完美。

### 第 3 周：启动 1-on-1

- 周一发通知：未来每周和每人 30 分钟 1-on-1，列出时间表
- 周二-周五：完成第一轮 7 人 1-on-1
- **优先顺序**：
  1. 高工资任务少的（场景 A）
  2. 工资低任务重的（场景 B）
  3. 看起来有离职风险的（场景 D）
  4. 其他

### 第 4 周：基于数据调整

- 看板跑了 3 周，有真实数据
- 拉每人 S/A/B/C 任务分布报表
- 对比职责书面化的预期，找出错配
- 重新分配任务，跟相关人单独沟通

### 第 5-8 周：固化 + 优化

- 项目里程碑预警机制上线（T-7、T-3、T-0 三次检查）
- 季度绩效初步框架成型
- 客户提单响应时长、bug 逃逸率等指标开始统计

## 七、常见坑预警

| 坑 | 表现 | 应对 |
| --- | --- | --- |
| 老板/销售跨过你直接找工程师 | 工程师被频繁打断，进度失控 | 立规矩走你这里，不行就找老板正式谈一次 |
| 站会变成"经理质询会" | 员工不敢说阻塞 | 你少说话，鼓励"我卡住了"是好事 |
| 看板变成"填表负担" | 字段太多没人填 | 必填字段控制在 8 个以内，其他选填 |
| 1-on-1 变成"催进度会" | 员工警惕，不说真话 | 进度永远在站会/看板谈，1-on-1 只谈人 |
| 高工资员工抵触新机制 | "我以前不这么做也好好的" | 1-on-1 沟通，强调是对所有人，不是针对他 |
| 客户问题永远 P0 | 团队疲于救火，无技术沉淀 | 强制留 20% 时间做技术沉淀，每月 review |

## 九、最后的话

这套方案的本质不是"管控"，而是**把隐性的东西显性化**：
- 隐性的任务难度 → 显性的 S/A/B/C
- 隐性的工作量 → 显性的看板卡
- 隐性的不满 → 显性的 1-on-1 渠道
- 隐性的项目状态 → 显性的红黄绿

显性化之后，问题才能讨论，讨论才能解决。

**实施过程中最重要的两件事：**
1. **你自己先用起来**。看板每天打开、站会每天开、1-on-1 每周做。下属看的是你的动作，不是你的话。
2. **第一个月别要求完美**。机制能跑起来就是胜利，细节后面慢慢优化。

祝顺利。
