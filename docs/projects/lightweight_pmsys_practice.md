# 轻量级研发项目管理系统实战（PMSys）

> 很多中小研发团队（尤其是多客户、多机型并行的软硬件团队）都有一张“祖传 Excel 项目一览表”：合并单元格满天飞、周报列横向拉到 70 多列、筛选排序全失效。本文记录从零把这张混乱 Excel 改造成一套 **Windows 零运维部署、局域网多人协同、内置 AI 周报助手** 的轻量级研发项目管理系统的完整过程与踩坑总结（文中已对具体公司与真实业务数据做脱敏处理）。

---

## 1. 痛点背景：为什么放弃 Excel 和多维表格？

### 原始 Excel 表的 5 个致命问题
1. **合并单元格模拟主从关系**：用「3 行 = 1 个项目（软件/硬件/业务各占一行）+ 数百处合并单元格」排版，导致 Excel 的筛选、排序、数据透视表全部失效；
2. **周报列横向无限生长**：从年初到年末横向累加 70+ 周次列，翻看最新进展要疯狂往右拉滚动条；
3. **多 Sheet 人工双写**：汇总表、活跃表、历史表字段重叠，全靠人工复制同步，数据频繁打架；
4. **脏数据混杂**：同一个日期列里同时混着真日期、Excel 序列号、纯文本（如“12月份”“待定”）；
5. **风险看不见**：几十上百个并行项目里，哪些节点超期、哪些周报暴露了卡点，经理只能逐行肉眼扫。

曾尝试迁移到通用多维表格，但在**自定义健康度规则、立项单解析、AI 周报深度整合以及按研发流程微调交互**上受限较多，最终决定做一套极简、可控的内部 Web 应用。

---

## 2. 务实的技术选型（一切以「零门槛落地」为先）

针对团队环境（Windows 办公机原生运行、无需 Docker/K8s、内网访问外网 CDN 极慢、希望双击即用），做了极度克制的架构取舍：

```text
浏览器（局域网同事）
   │  HTTP / 内网 HTTPS 反代
   ▼
FastAPI + Uvicorn（Windows 本机/内网 0.0.0.0:8000）
   ├─ frontend/index.html      ← Vue 3 + Element Plus 单文件 SPA（零构建、本地静态库）
   ├─ backend/health.py        ← 确定性三色健康度规则引擎
   ├─ backend/ai.py            ← DeepSeek API（无 Key 自动降级关键字 Mock）
   ├─ backend/launch_form.py   ← .doc / .docx 立项单解析预填
   ├─ backend/auth_security.py ← 登录限流、Cookie 会话、逐用户权限位
   └─ data/pm.db               ← SQLite 单文件数据库（支持 Excel 双向同步）
```

| 层级 | 技术栈 | 关键取舍 |
|---|---|---|
| **后端** | Python 3.10+ / FastAPI / SQLAlchemy 2.0 / SQLite | 单文件数据库，拷贝即备份；无需单独装 MySQL/PostgreSQL |
| **前端** | Vue 3 + Element Plus + Axios（单文件 HTML） | **零 Node.js / Vite 构建步骤**，所有 JS/CSS 库提前本地化到 `frontend/static/`，彻底摆脱外网 CDN 慢或断连 |
| **AI 能力** | DeepSeek API + 关键字 Mock 降级 | 有 API Key 时走大模型，无 Key 时自动降级保证功能不断链 |
| **文件互操作** | `openpyxl` + `python-docx` + `olefile` | 兼容老 `.doc` / 新 `.docx` 立项单识别，并支持 Excel 两步预览回灌 |
| **部署运维** | 纯 ASCII `start.bat` + `service.bat`（Windows 启动项 VBS） | 无需管理员权限安装系统服务，双击菜单完成开机常驻、查局域网 IP、放行防火墙 |

## 3. 数据清洗与模型设计

把原始多 Sheet 混乱 Excel 拆解重组为**规范化主从结构**：
- **项目主表（`Project`）**：以跨状态唯一 `UID`（如 `活跃-1`、`已完成-24`，导入遇到重复序号自动追加 `-dup2`）为主键，包含客户、机型、负责人、阶段节点（立项 / DVT / EIT / SVT / PP / MP）、完成度、状态与人工健康度覆盖字段；
- **周进度表（`WeeklyReport`）**：按 `(project_uid, week_code, role_type)` 纵向存储软件 / 硬件 / 业务三条线的每周进展，彻底告别 70+ 列横向表格；
- **用户与权限表**：支持注册审批、密码哈希与首次登录强制改密、细粒度功能权限位（编辑项目 / 填周报 / 导入导出 / 我的工作 / 数据质量）以及负责人别名绑定（把周报里的“张工”等简称映射到正式账号）。

### 针对脏数据的两个关键字段决策
1. **日期全部存 `TEXT`（ISO `YYYY-MM-DD`）而非 `DATE`**：原始表里混杂“12月中旬”“待定”等非标准文本，强转 `DATE` 会丢信息；存 `TEXT` 保留原文，规则引擎只对能解析为合法 ISO 日期的字段计算超期天数。
2. **完成度存 `REAL`（`0.0 ~ 1.0`）**：避免 `"60%"`、`"0.6"` 字符串混用，导出 Excel 时再统一附带百分比单元格格式。

## 4. 核心业务亮点

### 4.1 确定性「三色健康度」规则引擎（`health.py`）

不把健康度盲目交给黑盒大模型，而是用可解释、可回归验证的确定性规则自动分级（同时支持管理员手动覆盖并强制填写判定说明留痕）：

| 等级 | 触发规则 |
|---|---|
| 🔴 **严重（Critical）** | 节点超期 > 30 天且未完成；或最近周报命中**红词**（如“客户不接受 / 品质问题 / 项目取消”）；或时间进度落差 > 40% |
| 🟡 **注意（Warning）** | 节点超期 ≤ 30 天；或 7 天内临近节点且完成度 < 80%；或命中**黄词**（如“延迟 / 缺料 / 卡点”）；或时间进度差 20%–40%；或“需要协助”非空；或状态为暂停 |
| 🟢 **正常（Healthy）** | 已完成项目恒为绿，或未命中上述任何风险规则 |

**两个很关键的防误判设计**：
- **正向词抵消机制**：如果同一条周报里出现“已解决 / 已规避 / 已通过”，自动抵消该条记录里的负面词，避免历史已关闭的风险一直亮红灯；
- **缺报与风险解耦**：未填周报或久未更新归入独立的「待补周报 / 数据质量」清单，不污染项目健康度，避免“没写周报被误判成项目爆雷”。

### 4.2 多视图协同 + 立项单 / Excel 双向闭环

- **健康度看板**：默认按 🔴 / 🟡 / 🟢 三栏聚合，开周会直接按红黄绿过一遍；
- **周报矩阵视图**：行 = 项目，列 = 软件 / 硬件 / 业务，按周次切换，**不用点进项目详情就能在单元格内直接填报和对比三方进展**；
- **立项单自动识别（`.doc` / `.docx`）**：新建项目时上传立项单文档，后端解析表格与段落预填客户、机型、节点日期，并在界面标出缺失项由人工核对后提交；
- **Excel 安全回灌**：导出当前筛选结果为 `.xlsx`，允许习惯 Excel 批量编辑的同事改完后重新导入——导入强制走 **「预览变更（新增/修改/周报差异）→ 人工确认执行」** 两步走；
- **数据质量巡检面板**：自动扫描字段矛盾、负责人占位词、日期异常、重复周报、早于立项日的脏周报，支持定向修复或先预览再批量清理。

### 4.3 务实的 AI 辅助功能（DeepSeek + Mock 降级）

围绕研发经理与工程师的真实高频动作，接入了 4 个轻量级 AI 能力：
1. **周报一键结构化**：把一段随手写的自由文本自动拆解为 `✅ 本周完成 / 🔄 进行中 / ⚠️ 风险与卡点`；
2. **基于历史起草周报**：读取该项目近几周历史进展，一键生成本周周报草稿；
3. **自然语言项目查询**：在“AI 助手”里直接问「本周有哪些严重风险项目」「哪些项目需要业务跟进」；
4. **周会简报自动生成**：按指定周次汇总健康度变化、风险项与待协助事项，输出可直接发群的 Markdown 简报。

## 5. 实战踩坑记录（非常值得复用）

1. **Windows `.bat` 文件必须纯 ASCII**：Windows `cmd` 在执行前会按系统默认编码（GBK）解析整个批处理文件，UTF-8 中文注释或提示即使在文件头加 `chcp 65001` 也常引发语法错乱。所有 `.bat` 一律写纯英文 ASCII，中文提示留在 Python / Web 页面里。
2. **国内局域网不要依赖公共 CDN**：早期 HTML 通过 `unpkg.com` 引入 Vue 3 和 Element Plus，同事打开页面经常白屏转圈；将 6 个静态资源文件（约 1.7 MB）全部下载到 `frontend/static/` 本地托管后，内网毫秒级加载。
3. **FastAPI 静态路由顺序陷阱**：`/api/projects/health` 必须注册在 `/api/projects/{uid}` **之前**，否则请求 `/api/projects/health` 会被动态参数路由截胡，把 `"health"` 当成项目 `uid` 查库返回 404。
4. **单文件 Vue 模板反引号冲突**：无构建单文件 HTML 里直接在 JS 字符串写复杂模板时，反引号嵌套极易转义出错，拆清模板块或改用常规拼接更稳定。
5. **局域网 HTTP 下的 `Secure` Cookie 陷阱**：早期默认开启 Cookie `Secure` 属性，导致同事用 `http://192.168.x.x:8000` 登录成功却无法保持会话（浏览器拒绝在非 HTTPS 下发送 `Secure` Cookie）。需通过环境变量（如 `PMSYS_COOKIE_SECURE=0/1`）按是否配置了 HTTPS 反向代理显式开关，并同时提醒正式多人使用时务必补上内网 HTTPS。
6. **无管理员权限实现 Windows 开机常驻**：团队办公机往往没有管理员权限装 NSSM 系统服务。通过脚本往当前用户的 Windows「启动」文件夹写入一段静默启动 `.vbs`，再配合日志落盘（`logs/server.log`）与端口检测菜单，就能零权限门槛实现开机后台常驻。
